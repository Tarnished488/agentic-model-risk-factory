# 与《Agent 系统处理流程详解.md》的实现对照

本次检查覆盖现有 Discover / Document 及两个节点的交接。原流程文档作为设计基准保留；未编写的下游节点不以占位代码宣称完成。

## 已发现并修正的偏差

| 原流程要求 | 修改前 | 修改后 |
| --- | --- | --- |
| Document 按数据、变量、拟合、评分切块 | 每章重复发送全部材料，超限即失败 | document_sources.py 按阶段启发式及字符预算切窗，说明/字典/未分类代码完整保留，沿用原 source_id 和行号 |
| 每章单独生成 | 已有六章，但没有长文件处理 | 小模型全材料逐章生成；大模型把窗口完整打包为材料组，每章每组提炼最多 12 条事实后合并；跨组依赖明示未知 |
| 文档与原代码逐条自检 | 单次发送所有陈述和材料，容易超预算 | 陈述分批与所有材料组核对，避免与大量小窗口构成乘法调用；矛盾优先，逐批保存结果；代码检查覆盖率和引文 |
| consistency_report 每条包含陈述、结论、理由、证据 | 没有 statement 字段 | 报告直接包含 statement，文档中也显示逐条自检结果 |
| docs/<id>.md | 放在运行目录根部 | 放在每次运行的 docs/ 子目录，避免覆盖历史 |
| 格式错误携带错误信息重试 ≤2 次 | 仅笼统提示重试 | 反馈结构/证据/覆盖错误，初次调用加两次重试；Pydantic 错误不回显原始输入 |
| 超时指数退避与缓存 | Document 无退避与缓存 | 指数退避，经校验缓存按完整请求、Schema、服务和模型区分；可禁用缓存 |
| 失败后可审查结果 | Document 自检失败会丢弃生成内容 | 逐步保存章节，标记 partial_llm / needs_attention，技术失败不允许批准 |
| 人工关卡 2 可编辑、批准并锁定 | 完全缺失 | document_review.py 保存编辑后文档和报告快照，要求人工记录修改/未确认项处置 |
| 驳回携带意见回到 Document | 完全缺失 | 驳回快照保存意见，generate --feedback-review 校验同模型同 Discover 版本后将意见传入生成 |
| 批准文档成为 Redevelop 输入 | 无 loader | load_redevelop_input 校验批准、快照、文档、模型记录及原始源码，返回 ready_for_redevelop |
| 各节点共享状态 | 缺少下游字段及重试计数 | workflow_state.py 定义共享键，Document 保留上下游字段及实际重试次数 |
| 每次调用可追溯 | Document 缺输入摘要、用量、模型等 | Discover / Document 补调用摘要、模型、提示词版本、路径和服务用量；未知用量为 null |
| 每节点 MLflow run | 仅 Discover 支持 | Document 增加 --mlflow，记录节点 run、版本、模式、陈述/矛盾数量及运行产物 |

## Discover 保留的明确设计差异

| 原文建议 | 现状与理由 |
| --- | --- |
| 按文件名、目录、代码头注释自动归并模型 | 仍按直接子目录建立显式模型边界。名称或头注释相似不足以证明属于同一业务模型，避免误合并。使用前需按业务模型整理目录 |
| 对比文档日期与代码修改日期来判定过时 | 文件系统 modified_at 保留在清单中，但复制文件会改变该时间，不能单凭它判定语义过时。LLM 的 current/outdated 仍要求材料证据；证据不足保持 needs_review |
| 根据类型、用途、影响范围分级 | 当前仅在用途有证据时使用项目规则分级，并标记 provisional；没有银行影响范围和风险政策材料时保持未知，不编造正式银行分级 |

这些差异没有用无依据的自动判断强行改成示例值。模型清单采用嵌套 metadata 和结构化 evidence，表达原文示例中的信息并保留来源，而不要求与示例 JSON 的平面形状相同。

## 仍未实现或未联调的部分

- 人工关卡：已实现 CLI 审核和磁盘状态持久化；尚无 LangGraph interrupt / Streamlit 表格 UI，也没有自动恢复整个图的执行。驳回后由显式 generate 命令启动新运行。
- Redevelop：尚无 IR 解析、Python 模型生成、测试生成、隔离执行、Parity 阈值判定、最多三轮差异反馈循环或 Registry Staging 登记。
- Validate：尚无性能/稳定性/公平性计算、规则判定、报告解读、数字核对、PDF/Word 报告或人工关卡 4。
- Monitor：尚无窗口监控、告警和重新验证任务。
- 真实 LLM 和 MLflow：本地测试使用模拟响应/跟踪失败，不证明真实服务联调成功。
- 本次缓存只覆盖 Document；Discover 有退避，尚未引入持久化 LLM 缓存。

## 人工锁定的具体语义

批准生成独立文档副本和含文档全文、报告、审批的快照；loader 重新核验摘要和原始源码。编辑后快照保留最初自检报告，并明确记录 human_edited 与人工处置意见，不冒称修改稿已经重新通过 LLM 自检。

这是本地完整性机制，不能代替身份认证、数字签名或数据库审计。实际上线时需由平台补充这些能力。

## 在线联调后的调用规模修正（document-v3）

实际发现 v2 对 29 个源窗口逐章生成后累计 776 条陈述，自检形成约 26 × 29 次调用，运行时间不可接受。v3 保留源窗口和原行号，先将完整窗口按约 40000 字符预算打包；同一示例的材料只需一组。每章每组最多 12 条核心事实，重复陈述合并引用，按陈述批次与材料组交叉核对。六章仍分别生成，自检仍独立调用且检查全部材料。

新增单次运行实际 API 尝试预算（默认 30，含重试）、阶段进度输出、progress.json、调用耗时，以及 Ctrl+C 保存部分结果。预算耗尽或中断的运行不可批准。缓存命中不占 API 次数，缓存键随新提示词和分组改变，不能承诺复用旧版本的全部缓存。
